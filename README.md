# 弦上一刻（String Moment）项目README
 弦上一刻（String Moment）是一个连接音乐爱好者与琴行的一站式乐器抢购与服务平台，核心聚焦热门乐器限时秒杀、普通乐器购买核心场景，提供了完整的用户、商品、订单、秒杀与地址管理模块。

项目基于SpringBoot框架独立开发，目前已完成v1.0版本核心业务模块，重点攻克秒杀场景下的库存超卖、一人一单等核心痛点，通过合理的技术选型保障业务稳定性与基础性能；

后续将逐步集成RabbitMQ、SpringCloud、AI相关能力，持续迭代升级，完善高并发处理、分布式架构与智能化服务，进一步提升系统吞吐量与用户体验，完善平台生态。

## 核心技术栈

**后端技术栈**

1. 核心框架：SpringBoot、MyBatis
2. 数据存储

​	MySQL：存储商品、用户、订单、秒杀活动等核心业务数据

​	Redis：实现数据缓存、秒杀库存管控、下单防重复校验

3. 配套工具

​	Lua 脚本：保证库存扣减原子性，解决超卖问题

​	Spring Task：定时任务处理系统自动化逻辑

​	JWT：实现前后端无状态登录、用户与管理员角色鉴权

4. 事务控制：TransactionTemplate 编程式事务，保障数据一致性



**前端技术栈**

1. 基础框架：Vue 3.3 + Vite 5.4
2. 路由管理：Vue Router 4.2
3. 网络请求：Axios 1.6
4. 开发语言：原生 JavaScript

## 核心功能：商品秒杀模块设计与实现

本模块核心目标：解决秒杀高并发场景两大核心痛点 —— 商品超卖、用户重复下单（一人一单），采用 **Redis + Lua 原子脚本 + 定时任务** 技术方案，在保证高并发吞吐能力的同时，严格保障库存、订单数据一致性，各核心功能实现细节如下：

### 1. 定时任务：秒杀活动缓存生命周期同步（SeckillStatusTask）

定时任务每 10 秒执行一次，双向同步数据库与 Redis 缓存中的活动状态，统一管控缓存生命周期，减少无效缓存占用、保证活动数据实时准确。

- 活动开启逻辑：
  1. 从MySQL读取商品可用库存，预热到Redis缓存
  2. 从MySQL读取已购买用户列表，预热到Redis Set（防止活动重启后重复下单）
  3. 若无已购买用户，初始化空Set，避免后续查数据库

- 活动结束逻辑：清理该活动全部缓存 Key（库存 Key、用户下单 Set 等），释放 Redis 内存。



### 2. 核心下单流程（executeSeckill）

整体采用「Lua 缓存原子预校验 + 数据库持久化落单」两段式架构，把大量并发拦截逻辑下压至 Redis，减轻数据库压力，同时通过异常补偿机制保证数据一致。完整流程：

1. 基础前置校验

   统一校验秒杀活动是否有效、商品状态、用户收货地址合法性，提前拦截无效请求，减少缓存交互损耗。

2. 缓存容错兜底

   封装缓存恢复方法 `ensureRedisCache` ，若 Redis 缓存丢失、失效，自动从数据库重新加载：
      - 库存缓存：使用 `setIfAbsent` 原子操作避免并发写入
      - 用户购买记录缓存：使用分布式锁 + 双重检查，避免并发重建导致数据不一致
      - 若缓存重建超时，抛出业务异常阻断请求，防止重复下单漏洞

3. Lua 脚本原子预扣库存（并发核心）

   调用单条 Lua 脚本在 Redis 内部完成全量校验与库存扣减，全程单原子操作，杜绝多线程并发引发的超卖、重复下单问题。

4. 数据库生成订单

   Lua 脚本校验扣减成功后，同步创建普通订单、秒杀专属订单，完成业务数据持久化闭环。

5. 失败自动回滚补偿

   若数据库落单、写入流程抛出异常，通过异常捕获机制回滚 Redis 库存、删除用户下单记录，防止产生脏缓存数据。



### 3. Lua 原子脚本（高并发防超卖核心）

脚本在 Redis 单线程中完整执行，不存在并发分段操作，从底层杜绝并发漏洞。

- 传入参数：库存缓存 Key、用户下单记录 Set Key、用户 ID、活动状态、当前时间戳、活动开始时间、活动结束时间
- 内部执行逻辑：
  1. 时间戳优先校验：先判断当前时间是否在活动区间，规避定时任务状态同步延迟带来的异常；
  2. 防重复下单校验：通过 `SISMEMBER` 判断用户 ID 是否已存在下单集合，实现一人一单；
  3. 库存校验与扣减：`DECR` 原子扣减库存，库存不足直接终止流程；
  4. 记录下单用户：扣减成功后通过 `SADD` 将用户 ID 写入 Set，标记该用户已参与秒杀。

- 统一返回码定义：

​	0 = 下单成功；1 = 库存不足；2 = 重复购买；3 = 活动未开始；4 = 活动已结束



### 4. 定时任务：超时未支付订单自动关闭（OrderTimeoutTask）

每分钟执行一次，自动回收超时未支付订单库存，避免库存长期锁定无法释放，差异化区分普通订单、秒杀订单超时规则：

1. 超时规则差异化：普通订单超时 30 分钟关闭，秒杀订单仅 15 分钟，加快稀缺商品库存回流；
2. 任务执行策略：使用固定延迟执行（fixedDelay），等待上一轮任务完全执行完毕再开启下一轮，避免多任务并发更新订单；
3. 批量查询优化：批量读取待超时订单，避免循环单条查询数据库，提升处理性能；
4. 分事务独立处理：每条订单的状态更新、库存返还使用独立事务，单条订单处理失败不会中断整体任务，仅记录错误日志；
5. 库存返还区分逻辑：普通订单返还商品基础库存；秒杀订单单独返还活动专属秒杀库存。



### 5. 轻量管理员权限控制模块

基于用户表角色字段实现简易 RBAC 权限控制，无需复杂权限框架，适配小型项目管理后台需求：

1. 用户角色划分：用户表 role 字段区分身份，0 = 普通用户，1 = 管理员；
2. Token 角色携带：用户登录生成 JWT 时，将角色存入 Token 载荷，前端无需重复查询数据库；
3. 全局拦截器校验：自定义 `JwtInterceptor` 拦截所有 `/admin/**` 管理接口，强制校验 Token 内角色为管理员，直接拦截普通用户访问；
4. 独立管理员登录接口：单独提供 `/admin/login` 登录接口，二次校验账号管理员身份，避免普通用户账号登录后台；
5. 预置初始账号：数据库初始化种子数据内置管理员账号 admin/123456，项目部署后可直接登录后台。



## 环境依赖与快速启动

**环境依赖**

- 后端：JDK 1.8+、MySQL 5.7+/8.0、Redis 6.0+、Maven 3.6+
- 前端：Node.js 16+、npm 8+



**后端启动步骤**

1. 克隆项目：`git clone https://github.com/Say-OK/string-moment.git`
2. 导入数据库：执行 `sql/init_database.sql`（自动创建库、表、预置管理员和测试商品）
3. 修改配置：`src/main/resources/application.yml` 中配置MySQL和Redis连接信息
4. 启动后端：运行 `StringMomentApplication` 主启动类



**前端启动步骤**

1. 进入前端目录：`cd frontend`
2. 安装依赖：`npm install`
3. 启动开发服务器：`npm run dev`
4. 访问：`http://localhost:5173`



**默认账号**

- 管理员账号：admin / 123456（BCrypt加密存储）
- 测试用户：可自行注册



**接口测试**

- 用户端流程：注册/登录 → 商品浏览 → 秒杀下单 → 订单管理
- 管理端流程：管理员登录 → 商品管理 → 秒杀活动管理 → 订单发货
